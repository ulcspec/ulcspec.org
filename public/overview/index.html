WHY ULC EXISTS

Luminaire data is written for people, not machines.

The truth about a product lives across PDF datasheets, IES and LDT photometric files, installation documents, test reports, and compliance records — each formatted its own way, each written to be read one at a time.

Every design tool and AI agent that needs those values must re-extract them from documents made for the eye. What reaches the tools is an extraction layer's guess, not the manufacturer's source.

TODAY, ONE PRODUCT =

That worked while designers read one datasheet at a time. It breaks when an AI must read a hundred to answer a single question.

THE DATA MODEL

One record per attested photometric scenario.

Not one orderable SKU, and not automatically one IES file — one measured or declared scenario, connected to the configurations it covers and the evidence behind every value.

A
Applicability
Connects one scenario to the orderable configurations it represents.
P
Provenance
Connects each value to its source file, evidence type, and derivation method.

One scenario can cover thousands of SKUs.

01

COMPUTED INTELLIGENCE

One master record, two computed views.

Both views are generated by the reference builder and checked for parity. Neither can be typed in by the author.

INDUSTRY INFRASTRUCTURE

A shared data layer for the lighting industry.

ULC does not replace the PDF, IES, LDT, PIM, rep, distributor, or software platform. It gives them a common source of structured luminaire data.
